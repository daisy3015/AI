# pb-dashboard 빌드 절차

파마브로스 제품 개발 & 발주 관리 대시보드(`index.html`)를 만들어내는 폴더입니다.
**`index.html` 을 손으로 고치지 마세요.** 반드시 `build.py` 로 생성합니다.

---

## 매일 하는 일 (요약)

```bash
# 1) 저장소 clone
cd /tmp && rm -rf pb && git clone https://github.com/daisy3015/pb-dashboard.git pb && cd /tmp/pb

# 2) 노션 조회 결과(results 배열)를 build/notion.json 에 저장   ← MCP 로 수행
# 3) 빌드
python3 build/build.py --notion build/notion.json

# 4) 커밋 대상 3개만 푸시
git add index.html build/data.json build/notion.json
```

출력에 **`중단:`** 이 있으면 안전장치가 걸린 것입니다. **배포하지 말고** 사유를 보고하세요.
`--allow-empty` 로 우회하지 마세요.

---

## 파일 역할

| 파일 | 성격 | 설명 |
|---|---|---|
| `build.py` | 코드 | 빌드 스크립트. 아래 입력들을 합쳐 `index.html` 을 생성 |
| `template.html` | 고정 | 대시보드 UI 원본. `__DB_JSON__` 자리에 데이터가 주입됨 |
| `notion.json` | **매일 갱신** | 노션 조회 결과(`results` 배열). 2단계에서 덮어씀 |
| `sheet.json` | 스냅샷 | 구글시트 "제품 스펙 정리표" 제품 55건 |
| `orders.json` | 스냅샷 | 슬랙 발주 의뢰 59건 (매칭 판정 포함) |
| `config.json` | 고정 | 시트·노션·슬랙·Gmail 링크, 개발 프로세스 12단계 |
| `owners.json` | 거의 고정 | 노션 담당자 `user id` → 대시보드 표시명 |
| `carry.json` | 거의 고정 | 노션에서 사라진 속성(시작일·생성일) 보존값 |
| `data.json` | **자동 출력** | 이번 빌드 결과 스냅샷. 다음 실행의 "직전 대비 변경" 비교 기준 |

`index.html` 은 저장소 루트에 생성됩니다 (GitHub Pages 가 그 파일을 서비스함).

---

## ⚠️ 중요 — 매일 갱신되는 건 노션뿐입니다

`build.py` 는 네트워크에 접속하지 않습니다. 따라서:

- **노션** → 매일 새로 반영됩니다 ✅
- **구글시트(제품 55건)** → `sheet.json` 스냅샷 고정 ❌
- **슬랙 발주(59건)** → `orders.json` 스냅샷 고정 ❌

시트에 신제품이 추가되거나 슬랙에 새 발주가 올라와도 **자동 반영되지 않습니다.**
반영이 필요하면 `sheet.json` / `orders.json` 을 갱신해 커밋해야 합니다.
(현재 스냅샷 기준일: 2026-07-28)

## 안전장치

걸리면 `중단: …` 을 출력하고 종료코드 1 로 끝냅니다. **이때 `index.html` 은 건드리지 않습니다.**

| 조건 | 메시지 |
|---|---|
| 노션 결과 0건 | `중단: 노션 조회 결과가 0건입니다 …` |
| 총 항목이 직전의 80% 미만 | `중단: 총 항목이 급감했습니다 …` |
| 노션 항목이 직전의 50% 미만 | `중단: 노션 항목이 급감했습니다 …` |
| 입력 파일 없음 / JSON 깨짐 | `중단: … 파일이 없습니다` |
| 템플릿의 `__DB_JSON__` 이 1개가 아님 | `중단: 템플릿의 자리표시자가 …` |

임계값은 `build.py` 상단 상수(`MIN_TOTAL_RATIO` 등)에서 조정합니다.

## 자주 필요한 관리 작업

### 새 담당자가 노션에 배정됐을 때

`모르는 담당자 ID: <uuid> (페이지: …)` 경고가 나오면 `owners.json` 에 추가합니다.

```json
{
  "380d872b-594c-8109-a7e5-00023a1633e2": "Daisy",
  "268d872b-594c-8126-90e1-0002b442f22a": "Silvia",
  "1fcd872b-594c-81db-95c7-000216e61fe4": "Jake"
}
```

ID 는 노션 MCP `get-users` 로 확인합니다. 등록 전까지 그 담당자는 대시보드에서 "미지정" 으로 표시됩니다.

### 시트 / 발주 스냅샷 갱신

`sheet.json` 은 항목 배열, `orders.json` 은 발주 배열입니다. 형식을 유지한 채 편집하면 됩니다.
`orders.json` 의 각 발주에 `match` 키가 **있으면 그 판정을 그대로 존중**합니다.
`match` 키가 아예 없는 발주만 `build.py` 가 자동 매칭을 시도하고 경고를 남깁니다
(제품명 포함 관계로 판단하므로, 결과를 확인하고 필요하면 손으로 고정하세요).

## 노션 ↔ 시트 매칭 규칙

노션 페이지와 시트 제품이 같은 물건인지 판단하는 규칙입니다.

1. 이름을 정규화 (유니코드 정규화 → 소문자 → 영숫자·한글만 남김)
2. **완전일치** 또는 **노션 이름이 시트 이름을 포함**하면 후보
3. 시트 이름의 정규화 길이가 4자 이상일 때만 후보로 인정
4. 후보가 **정확히 1건일 때만** 병합 → `src: "both"`, 노션 이름은 `devName` 에 보존
5. 후보가 없으면 노션 단독 항목(`src: "notion"`), 2건 이상이면 경고 후 단독 처리

> 반대 방향(시트 이름이 노션 이름을 포함)은 **쓰지 않습니다.**
> 예: 노션 "칼슘마그네슘" 과 시트 "마시는 마그네슘 200" 은 다른 제품인데
> 역방향 규칙을 넣으면 잘못 병합됩니다.

`src` 값 의미 — `sheet`: 시트에만 / `notion`: 노션에만 / `both`: 양쪽 매칭

## 알려진 제약

**`시작일`·`생성일`** — 현재 노션 DB(`상품기획 TEST`)에는 시작일 속성이 없고,
`createdTime` 은 2026-07-28 일괄 등록 시각으로 고정돼 있습니다.
기존 대시보드에 표시되던 값이 사라지지 않도록 `carry.json` 에 페이지별로 보존해 두었습니다.

노션에 `시작일` 속성을 다시 만들면:

1. 2단계 SQL 에 `"date:시작일:start" AS start` 를 추가
2. `build.py` 의 `notion_to_item()` 에서 `"start": kept.get("start")` 를
   `"start": datepart(row.get("date:시작일:start")) or kept.get("start")` 로 변경

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| `중단: 노션 조회 결과가 0건입니다` | MCP 연결·권한, SQL 의 collection URL |
| `중단: … 급감했습니다` | 노션에서 대량 삭제가 실제로 있었는지. 맞으면 임계값 조정 후 재실행 |
| 담당자가 "미지정" 으로 나옴 | `owners.json` 에 해당 ID 등록 |
| 새 제품이 안 보임 | 노션이 아니라 시트에 추가된 것일 수 있음 → 위 "매일 갱신되는 건 노션뿐" 참고 |
| 페이지가 백지 | `template.html` 손상 여부. `git checkout build/template.html` 로 복구 |

빌드는 멱등합니다 — 같은 `notion.json` 으로 여러 번 돌려도 결과는 같습니다
(`synced_at` 시각만 갱신됨).
